سئوی مدرن برای ۲۰۲۵–۲۰۲۶

یک راهنمای ساختاریافته درباره زیرساخت فنی، محتوای معنایی، اعتبار، رضایت کاربر و برنامه اجرایی ۳۰ روزه — شامل AI Overviews گوگل. نسخه آزمایشی «SGE» امروز معمولاً با همین نام شناخته می‌شود.

۱. سه‌گانه بنیادین

سئوی فنی، درون‌صفحه‌ای و برون‌صفحه‌ای یک سیستم واحدند. قوت در دو بخش، ضعف بخش سوم را جبران نمی‌کند.

فنی — دسترسی‌پذیری

کشف URL، دریافت منابع، رندر صفحه، درک روابط، انتخاب کنونیکال و ایندکس کارآمد محتوای هدف.

درون‌صفحه — معنا

موضوع صفحه، نیت جستجو، کامل و معتبر بودن ادعاها، ارتباط با صفحات دیگر و اقدام بعدی کاربر.

برون‌صفحه — اعتماد بیرونی

شناخت مستقل برند، پیوند موضوعی، ارجاع‌های مرتبط و قابل‌اعتماد، و مشروعیت سازمان.

تشبیه دانشگاه

  • سئوی فنی ساختمان، جاده، تابلو، برق و دسترسی است.
  • محتوا کیفیت اساتید و برنامه درسی است.
  • برون‌صفحه اعتبار، ارجاع‌ها و همکاری‌های علمی است.

اگر ساختمان غیرقابل‌دسترسی باشد، کسی با اساتید روبه‌رو نمی‌شود. اگر برنامه درسی ضعیف باشد، اعتبار نمی‌تواند دانشجو نگه دارد. اگر کسی دانشگاه را نشناسد، حتی بهترین دوره‌ها دیده نمی‌شوند.

بک‌لینک قوی معمولاً ایندکس‌نشدن را نجات نمی‌دهد. سئوی فنی بی‌نقص محتوای نازک را ارزشمند نمی‌کند. محتوای عالی بدون اعتبار اغلب در جستجوهای رقابتی می‌بازد.

۲. ضروریات سئوی فنی

زیرساختی که موتور جستجو قبل از هر رتبه‌ای به آن نیاز دارد.

۲.۱ خط لوله مدرن جستجو

کشف (Discovery)

گوگل URLها را از لینک داخلی، لینک خارجی، نقشه XML، ریدایرکت، URLهای قبلی و فیدها پیدا می‌کند. بودن در sitemap به‌معنی تضمین کراول یا ایندکس نیست.

کراول (Crawling)

ربات وضعیت HTTP، HTML، هدرها، ریدایرکت و دستورات robots را می‌گیرد.

  • 200 صفحه موفق
  • 301/308 ریدایرکت دائمی
  • 302/307 ریدایرکت موقت
  • 404/410 حذف‌شده
  • 5xx خطای سرور
  • Soft 404: کد ۲۰۰ برمی‌گرداند اما گوگل آن را خالی یا حذف‌شده می‌داند

رندر (Rendering)

  1. دانلود HTML
  2. پارس محتوای قابل‌دیدن و لینک‌ها
  3. صف‌بندی CSS/JavaScript
  4. اجرای JS
  5. ساخت DOM رندرشده
  6. ارزیابی محتوا، لینک، کنونیکال، داده ساخت‌یافته و چیدمان

محتوای حیاتی سئو را ترجیحاً در HTML سمت سرور بگذارید. قبل از متن و لینک‌های داخلی ضروری، به کلیک، اسکرول یا API فقط‌مرورگر وابسته نشوید. لینک واقعی <a href> اولویت دارد.

ایندکس (Indexing)

گوگل تصمیم می‌گیرد ایندکس کند یا نه، کدام URL کنونیکال است، صفحه برای کدام کوئری‌ها مناسب است، تکراری است یا نه، و سیستم‌های کیفیت/سیاست آن را سرکوب می‌کنند یا نه. کراول‌شده ≠ ایندکس‌شده.

بودجه کراول، رندر و ایندکس

بودجه کراول

بیشتر برای سایت‌های بزرگ یا پرتغییر مهم است. تحت‌تأثیر ظرفیت سرور، تقاضای کراول، اهمیت لینک داخلی، تکراری‌ها، فیلترها، زنجیره ریدایرکت، پارامترها و تازگی محتواست.

  • فضاهای واقعاً بی‌فایده را با robots.txt محدود کنید
  • صفحاتی که گوگل باید noindex آن‌ها را بخواند را مسدود نکنید
  • URLهای فیلتر تکراری را یکپارچه کنید
  • زنجیره ریدایرکت را حذف کنید؛ کد وضعیت درست برگردانید
  • موجودی مهم را لینک داخلی بدهید
  • sitemap را فقط با URLهای کنونیکال و قابل‌ایندکس نگه دارید

بودجه رندر

صفحات سنگین جاوااسکریپت کشف محتوا را کند می‌کنند. محتوای اصلی را سمت سرور رندر کنید، پیشرفت تدریجی بدهید، کنونیکال/متا فقط‌کلاینت نگذارید، باندل JS را سبک کنید و HTML رندرشده را در Search Console ببینید.

کیفیت ایندکس

گوگل انتخابی ایندکس می‌کند. دسته‌های نزدیک‌به‌تکراری، تگ‌های خالی، جستجوی داخلی، ترکیب پارامترها و وریانت‌های نازک مجموعه ایندکس را ضعیف می‌کنند.

۲.۲ Core Web Vitals

داده میدانی را در صدک ۷۵ برای موبایل و دسکتاپ جدا ببینید. ابزار آزمایشگاهی تشخیص می‌دهد؛ CrUX / Search Console / PSI تصمیم «خوب» را می‌سازند.

LCP — بزرگ‌ترین رنگ محتوا

سرعت ظاهر شدن محتوای اصلی قابل‌دید.

خوب ≤ ۲٫۵ ثانیه نیاز به بهبود ۲٫۵–۴٫۰ ضعیف > ۴٫۰
  • تصویر قهرمان با AVIF/WebP و srcset واکنش‌گرا
  • تصویر LCP را lazy-load نکنید؛ fetchpriority="high" بگذارید
  • preload گزینشی فونت/تصویر؛ CSS حیاتی حداقلی inline
  • حذف CSS/JS مسدودکننده رندر؛ بهبود TTFB (کش، CDN، دیتابیس)
  • از اسلایدری که قهرمان اول را دیر نشان می‌دهد پرهیز کنید

INP — تعامل تا رنگ بعدی

پاسخ‌گویی در تعاملات کاربر.

خوب ≤ ۲۰۰ میلی‌ثانیه نیاز به بهبود ۲۰۰–۵۰۰ ضعیف > ۵۰۰
  • کارهای JS طولانی‌تر از حدود ۵۰ms را بشکنید؛ اسکریپت شخص‌ثالث را کم کنید
  • جستجو/فیلتر را debounce کنید؛ از event delegation استفاده کنید
  • از اندازه‌گیری مکرر DOM و سپس نوشتن پرهیز کنید؛ لیست‌های خیلی بلند را مجازی کنید
  • محاسبات سنگین در Web Worker؛ اسکریپت مخصوص صفحه فقط همان‌جا
  • UI را فوری به‌روز کنید، بعد کار async سنگین را شروع کنید

CLS — جابه‌جایی تجمعی چیدمان

حرکت ناخواسته عناصر روی صفحه.

خوب ≤ ۰٫۱ نیاز به بهبود ۰٫۱–۰٫۲۵ ضعیف > ۰٫۲۵
  • برای تصویر و ویدیو width/height بگذارید؛ برای تبلیغ و embed فضای ثابت/aspect-ratio
  • بنر را بالای محتوای موجود هل ندهید
  • فونت را درست preload کنید؛ متریک فونت جایگزین سازگار
  • انیمیشن با transform نه با ویژگی‌های layout
  • برای اعلان، گالری و کاروسل فضا رزرو کنید

۲.۳ ایندکس موبایل‌اول

گوگل معمولاً نسخه موبایل را نسخه اصلی می‌داند. موبایل باید محتوای اصلی، سرفصل‌ها، لینک داخلی، داده ساخت‌یافته، alt تصویر و دستورات robots/کنونیکال معادل داشته باشد.

طراحی واکنش‌گرا (ترجیحی): یک URL، یک HTML، تطبیق با CSS. خطای برابری محتوا، ریدایرکت و تکراری کمتر.

سرویس پویا: همان URL با HTML متفاوت بر اساس دستگاه. ریسک: تشخیص اشتباه User-Agent، کش HTML دسکتاپ برای موبایل، نبود schema، ناسازگاری برای Googlebot. محتوای حیاتی سئو را فقط برای «ساده‌سازی» موبایل مخفی نکنید.

۲.۴ معماری سایت

سلسله‌مراتب معمول: خانه → دسته اصلی → زیردسته → محصول، خدمت یا مقاله. صفحات مهم معمولاً باید در حدود سه گام لینک داخلی معنادار از یک هاب اصلی قابل‌دسترسی باشند.

سایت کاملاً تخت روابط موضوعی را ضعیف می‌کند؛ عمق بیش‌ازحد محتوا را پنهان می‌کند. از سلسله‌مراتب معنایی کم‌عمق استفاده کنید: چند بخش پایدار بالا، زیردسته‌های متمرکز، لینک زمینه‌ای، بردکرامب.

  • یک هدف اصلی برای هر صفحه قابل‌ایندکس
  • چند صفحه را روی یک نیت واحد نگذارید
  • از مفهوم کلی به جزئی لینک دهید؛ صفحات پشتیبان به ستون برگردند
  • به صفحات اولویت‌دار لینک داخلی مرتبط بیشتری بدهید
  • انکر توصیفی؛ نه «اینجا کلیک کنید»

نقشه XML: فقط URL کنونیکال، قابل‌ایندکس، با کد ۲۰۰، ارزشمند و با lastmod درست. سایت بزرگ را جدا کنید (محصول، دسته، مقاله، صفحه). sitemap پیشنهاد می‌دهد؛ رتبه نمی‌سازد.

۲.۵ کنونیکال و hreflang

<link rel="canonical" href="https://example.com/preferred-url/" />

برای صفحات عادی قابل‌ایندکس، کنونیکال خودارجاع بگذارید. اشتباهات رایج: کنونیکال صفحه‌بندی به صفحه ۱؛ کنونیکال محصول متمایز به دسته کلی؛ کنونیکال به ریدایرکت یا ۴۰۴؛ سیگنال متناقض sitemap/لینک/کنونیکال؛ ترویج فیلترهایی که کنونیکال می‌کنید. کنونیکال راهنما است — با ریدایرکت، لینک و sitemap تقویتش کنید.

<link rel="alternate" hreflang="fa-IR" href="https://example.com/fa/page/" />
<link rel="alternate" hreflang="en-US" href="https://example.com/en/page/" />
<link rel="alternate" hreflang="x-default" href="https://example.com/page/" />

hreflang: خودارجاع، دوطرفه، URL کنونیکال قابل‌ایندکس، کد معتبر، بومی‌سازی واقعی. کنونیکال معمولاً به همان زبان اشاره می‌کند، نه یک زبان جهانی واحد.

۳. استراتژی محتوا و معنای درون‌صفحه

فراتر از تراکم کلمه کلیدی: مفهوم، زمینه، تجاری‌بودن، خوشه موضوعی، E-E-A-T، اسکیما و AI Overviews.

۳.۱ سه C تحقیق کلمه کلیدی

مفهوم (Concept)

موجودیت یا مسئله‌ای که کاربر می‌جوید؛ مثلاً کلرید سدیم، تأمین‌کننده مواد شیمیایی آزمایشگاهی، اتانول گرید آنالیتیکال. واژگان بسازید: نام‌ها، مترادف‌ها، اصطلاحات صنعتی، کاربردها، مشکلات، نتایج و ویژگی‌ها.

زمینه (Context)

شرایط: آموزشی در برابر تجاری، آزمایشگاهی در برابر صنعتی، مبتدی در برابر متخصص، محلی در برابر بین‌المللی، مقایسه در برابر عیب‌یابی. زمینه عمق، واژگان، شواهد و قالب را تعیین می‌کند.

تجاری‌بودن (Commerciality)

فاصله تا اقدام: خرید/قیمت/تأمین‌کننده؛ بهترین/بررسی/مقایسه؛ گرید/خلوص/CAS؛ چیست/کاربرد/ایمنی. صفحه تراکنشی را به زور روی کوئری اطلاعاتی گسترده نگذارید.

SERP زنده را ببینید. اگر گوگل عمدتاً صفحه دسته می‌آورد، مقاله از نظر ساختاری اشتباه است — هرچقدر هم کلمه کلیدی داشته باشد.

۳.۲ خوشه موضوعی در برابر سیلو

سیلو: شاخه‌های موضوعی سخت‌گیرانه — خوب برای ناوبری و URL؛ ریسک مسدود کردن لینک‌های مفید بین موضوعات.

خوشه موضوعی: یک صفحه ستون + صفحات پشتیبان متمرکز — پوشش موضوعی، نیت‌های مختلف، لینک داخلی طبیعی، تمرکز اعتبار روی یک موجودیت.

سلسله‌مراتب شفاف داشته باشید و لینک‌های خوشه‌ای مرتبط و انعطاف‌پذیر بگذارید.

  1. موضوع را انتخاب کنید با ارتباط تجاری، چند زیرنیت، تخصص واقعی و محصولات/خدمات متصل (مثلاً مواد شیمیایی آزمایشگاهی).
  2. نیت‌ها را نقشه کنید: گرید و خلوص، ایمنی، کاربرد، بسته‌بندی، انتخاب تأمین‌کننده، مقررات، مقایسه، خانواده‌های شیمیایی.
  3. ستون: تعریف موضوع در ۱۰۰–۱۵۰ واژه اول؛ پوشش زیرموضوع‌های اصلی؛ لینک به هر خوشه مهم؛ تصویر یا ابزار تصمیم‌گیری اصلی؛ استناد به منابع اولیه؛ تظاهر نکنید یک صفحه همه سؤالات تخصصی را جواب می‌دهد.
  4. یک صفحه خوشه برای هر نیت متمایز: اطلاعات غیرتکراری، لینک به ستون و خوشه‌های مجاور، گام بعدی روشن.
  5. هم‌پوشانی را حل کنید: برای هر کوئری یک URL ترجیحی؛ ادغام، ریدایرکت یا جابه‌جایی صفحات رقیب.

۳.۳ E-E-A-T بدون گفتن «ما متخصصیم»

E-E-A-T یک چارچوب کیفیت است، نه یک امتیاز رتبه‌بندی واحد.

  • تجربه (Experience): عکس اصلی محصول، نتیجه تست، اسکرین شات فرایند، کیس‌استادی با تاریخ و نتیجه، محدودیت‌ها، روش‌شناسی.
  • تخصص (Expertise): اصطلاحات دقیق، نویسنده و مدرک، بازبینی‌کننده، استناد به منابع اولیه، مشخصات و ایمنی کامل، تاریخچه به‌روزرسانی.
  • مرجعیت (Authoritativeness): ارجاع صنعتی، رابطه با تأمین‌کننده/تولیدکننده، ذکر در نشریات حرفه‌ای، داده موجودیت یکدست، پروفایل نویسنده متصل به هویت واقعی.
  • اعتماد (Trustworthiness): هویت و تماس، HTTPS، سیاست مرجوعی/ارسال/حریم خصوصی، شفافیت قیمت و موجودی، اصالت محصول، منابع و تاریخ بازبینی، نظرات واقعی با سیاست تعدیل، مسیر اصلاح خطا.

صفحه محصول با مشخصات، گواهی، منبع‌یابی، کاربرد، ایمنی، تصویر واقعی و مسئولیت‌پذیری محتوا ثابت می‌کند — نه با شعار.

۳.۴ داده ساخت‌یافته — پنج نوع مهم

مارکاپ باید با محتوای قابل‌دید یکی باشد. اسکیما ضمانت ریچ‌ریزالت نیست.

  1. Organization — هویت شرکت، لوگو، تماس، پروفایل‌ها.
  2. BreadcrumbList — موقعیت در سلسله‌مراتب؛ ممکن است بردکرامب SERP را بهتر کند.
  3. Product — قیمت، موجودی، SKU، برند، امتیاز، پیشنهاد. فقط برای صفحه محصول واقعی.
  4. Article — عنوان، نویسنده، تاریخ انتشار/به‌روزرسانی، تصویر.
  5. FAQPage — ساختار سؤال و جواب. نمایش FAQ در نتایج امروز بسیار محدود است؛ روی سایت تجاری معمولی حساب نکنید.

همچنین: WebSite، LocalBusiness، VideoObject، Review، MerchantReturnPolicy، OfferShippingDetails. با Rich Results Test و Schema.org اعتبارسنجی کنید.

۳.۵ بهینه‌سازی برای AI Overviews

اسکیمای ویژه «AI Overview» وجود ندارد و تضمینی برای ذکرشدن نیست. متن را قابل‌استخراج و شواهدمحور کنید:

  • بلافاصله بعد از هر عنوان پاسخ مستقیم بدهید
  • هر بخش یک سؤال یا ادعا؛ موجودیت‌ها unambiguous
  • اول واقعیت کوتاه، بعد nuance؛ استناد به منبع اولیه
  • تاریخ، واحد، شرایط و محدودیت‌ها
  • پژوهش، مقایسه یا مشاهده اصلی
  • جدول فقط وقتی داده را روشن می‌کند
  • نویسنده/سازمان شفاف؛ URL پایدار؛ تاریخ به‌روزرسانی قابل‌دید
  • محتوای مهم در HTML رندرشده؛ قطعیت بی‌پشتیبانی نگذارید

بلوک پاسخ قوی: (۱) جواب ۱–۲ جمله‌ای، (۲) شواهد، (۳) شرایط، (۴) منبع، (۵) سؤال بعدی مرتبط.

۴. مکانیک اعتبار برون‌صفحه

فیزیک مدرن لینک‌سازی: اول مرتبط‌بودن، بعد اعتبار؛ داده منحصربه‌فرد مهم‌تر از طول متن.

اعتبار در برابر مرتبط‌بودن

مرتبط‌بودن مشخص می‌کند لینک از نظر موضوعی معنا دارد یا نه. اعتبار روی میزان اعتماد سیگنال اثر می‌گذارد. لینک زمینه‌ای از یک نشریه تخصصی معتبر معمولاً از لینک بی‌ربط یک دامنه معروف بهتر است.

فرصت‌ها را با مرتبط‌بودن موضوعی، استقلال تحریریه، کیفیت صفحه، مخاطب واقعی، زمینه اطراف لینک، پتانسیل ترافیک ارجاعی، اعتبار دامنه و طبیعی‌بودن انکر بسنجید.

استراتژی‌های سفید

روابط عمومی دیجیتال (Digital PR)

دارایی خبرساز: داده بازار اصلی، نظرسنجی، نظر کارشناسی درباره رویداد جاری، ابزار/دیتاست عمومی، آزمایش شفاف، تحلیل مقررات یا قیمت.

  1. خبرنگاران حوزه را پیدا کنید
  2. ببینید چه شواهدی را مرتب نقل می‌کنند
  3. شواهد تازه بسازید — نه تفسیر دوباره مطالب دیگران
  4. یافته کلیدی را کوتاه پیچ کنید؛ روش‌شناسی و فایل قابل‌دانلود بدهید
  5. ذکرها را رصد کنید؛ در صورت نیاز درخواست attribution بدهید

لینک شکسته (Broken-link building)

  1. صفحات مرتبط با ارجاع خارجی شکسته پیدا کنید
  2. هدف منبع اصلی را بفهمید
  3. جایگزین واقعاً مناسب بسازید
  4. به ویراستار بنویسید: URL شکسته، محل در صفحه، جایگزین شما، دلیل برابری

پیام انبوه عمومی نفرستید.

آسمان‌خراش ۲٫۰ (Skyscraper 2.0)

تمایز با طول نیست؛ با سودمندی منحصربه‌فرد است: داده اختصاصی، آزمایش، ابزار تعاملی، روش بهتر، داده منطقه‌ای، مصاحبه کارشناسی، به‌روزرسانی منظم، قالب قابل‌دانلود، دیتاست باز. ده هزار واژه عمومی از یک صفحه کوتاه با شواهد اصلی ضعیف‌تر است.

ابزار Disavow

اکثر سایت‌ها نباید به‌طور معمول disavow کنند. گوگل بسیاری از لینک‌های اسپم را خودش نادیده می‌گیرد. فقط وقتی اقدام دستی برای لینک غیرطبیعی دارید، سابقه ساخت لینک دستکاری‌شده دارید، یا الگوی مستندی هست که حذف دستی‌اش ممکن نیست.

ریسک‌ها: disavow لینک خوب، کاهش بی‌مورد اعتبار، اعتماد به امتیاز «سمی» شخص‌ثالث. اگر لازم شد: بک‌لینک‌ها را خروجی بگیرید، الگو را مستند کنید، حذف را امتحان کنید، در سطح دامنه با احتیاط disavow کنید، شواهد تاریخ‌دار نگه دارید.

۵. تجربه کاربری و حلقه بازخورد تعامل

رضایت را بهینه کنید؛ متریک‌های فولکلور را مثل دکمه رتبه‌بندی نبینید.

Pogo-sticking، Dwell Time و CTR

Pogo-sticking (کلیک، بازگشت سریع، انتخاب نتیجه دیگر) می‌تواند نارضایتی را نشان دهد، اما متریک رتبه‌بندی مستقل مستندی نیست. بازگشت سریع گاهی یعنی جواب فوری پیدا شده است.

Dwell time عامل رتبه‌بندی جهانی تأییدشده نیست. زمان نشست را مصنوعی طولانی نکنید.

CTR به جایگاه، نیت، برند، ویژگی‌های SERP، عنوان و اسنیپت بستگی دارد. برای تشخیص مفید است؛ گوگل CTR ارگانیک معمولی را اهرم مستقیم ساده رتبه‌بندی معرفی نکرده است.

عنوان و متا دیسکریپشن

عنوان قوی با نیت اصلی هم‌خوان است، موجودیت را نام می‌برد، تمایز می‌دهد، در عرض نمایش معمول جا می‌شود، boilerplate تکراری سایت‌گسترده ندارد و صادق است.

  • [محصول/موضوع]: مشخصات، کاربرد و قیمت
  • چگونه [نتیجه]: [روش مشخص]
  • [گزینه الف] در برابر [گزینه ب]: تفاوت‌ها برای [کاربرد]
  • خرید [محصول] — گرید، بسته‌بندی و موجودی

متا: مسئله کاربر، ارزش مشخص، شواهد یا تمایز، اقدام مناسب. فوریت جعلی و پنهان‌کردن جواب برای کنجکاوی ارزان ممنوع.

کنجکاوی خوب: قبل از سفارش، گرید آزمایشگاهی، سطح خلوص و بسته‌بندی را مقایسه کنید.
کلیک‌بیت: باور نمی‌کنید دانشمندان درباره این ماده چه کشف کرده‌اند!

رتبه تشخیص می‌دهد. ترافیک دامنه دسترسی را نشان می‌دهد. تبدیل کسب‌وکار را می‌گرداند.

ایندکس

بررسی کنید: ایندکس‌شده، کراول‌شده ولی ایندکس‌نشده، کشف‌شده ولی ایندکس‌نشده، تکراری بدون کنونیکال انتخاب‌شده، صفحه جایگزین با کنونیکال درست، soft 404، خطای سرور، بلاک robots. در URL Inspection: کنونیکال اعلامی در برابر انتخاب گوگل، تاریخ کراول، موبایل، صفحه رندرشده، واجد شرایط بودن.

الگوهای عملکرد

  • ایمپرشن بالا، CTR پایین ← عنوان/اسنیپت یا نیت
  • جایگاه ۵–۱۵ ← محتوا، لینک داخلی، اعتبار
  • کلیک پایین با رتبه ثابت ← تقاضا یا چیدمان SERP
  • چند URL برای یک کوئری ← هم‌پوشانی
  • ایمپرشن رو به رشد ← قبل از رقبا همان صفحه را گسترش دهید

حداقل ۲۸ روز را با دوره معادل قبل مقایسه کنید؛ فصلی‌بودن را در نظر بگیرید.

ممیزی سئو در ۷ گام

  1. دسترسی و ایندکس: robots، متا robots، کد وضعیت، sitemap، کنونیکال، کنونیکال انتخابی گوگل، noindex تصادفی، یتیم‌ها.
  2. معماری: عمق کلیک، ناوبری، بردکرامب، انکر، لینک شکسته، زنجیره ریدایرکت.
  3. تکراری و کم‌ارزش: پارامتر، فیلتر، تگ، جستجوی داخلی، صفحه‌بندی، محصول نزدیک‌به‌تکراری، دسته نازک، نسخه HTTP/HTTPS و www.
  4. عملکرد: CWV میدانی، TTFB، منبع LCP، کار طولانی JS، CLS، برابری موبایل، HTML رندرشده.
  5. درون‌صفحه: عنوان و H1 یکتا، نیت، پوشش موجودیت، سرفصل، alt، هم‌پوشانی، تازگی.
  6. اعتماد و اسکیما: نویسنده، منابع، جزئیات سازمان، سیاست‌ها، اطلاعات محصول، اعتبار اسکیما، HTTPS.
  7. اعتبار و نتیجه: دامنه ارجاعی مرتبط، سابقه لینک دستکاری، ذکر برند، ترکینگ تبدیل، درآمد لندینگ ارگانیک، بک‌لاگ اولویت‌دار.

یافته‌ها را با تأثیر × اطمینان ÷ هزینه اجرا رتبه‌بندی کنید.

۷. نقشه راه صفر تا قهرمان — ۳۰ روز

اول بالاترین بازده مرکب. فرض: هنوز سایتی نیست.

هفته ۱
زیربنا

روز ۱: یک تبدیل اصلی، مشتری هدف، مسئله حل‌شده، KPI پایه.

روز ۲: ۱۰ رقیب؛ نوع صفحات، قوی‌ترین دسته/راهنما، ویژگی SERP برای ۲۰ کوئری تجاری.

روز ۳: نقشه ۱۰ موضوع تراکنشی، ۱۰ مقایسه‌ای، ۲۰ اطلاعاتی — برای هر نیت یک URL ترجیحی.

روز ۴: ۳–۷ بخش اصلی، زیردسته، نقشه ستون/خوشه، قرارداد URL، بردکرامب.

روز ۵: قالب واکنش‌گرا، HTTPS، هاست سریع، permalink تمیز، Analytics، Search Console، ترکینگ تبدیل.

روز ۶: درباره ما، تماس، حریم خصوصی، قوانین، ارسال/مرجوعی در صورت نیاز، پروفایل نویسنده و سازمان.

روز ۷: استاندارد محتوا: یک نیت، مالک نام‌دار، تاریخ به‌روزرسانی، سهم اصلی، منابع، لینک داخلی، CTA قابل‌اندازه‌گیری.

هفته ۲
محتوا

روز ۸: طرح ستون — تعریف، معیار تصمیم، زیرموضوع، اشتباهات رایج، شواهد، لینک خوشه.

روز ۹: انتشار ستون: جواب اصلی در ابتدای متن؛ پوشش زیرنیت‌های مهم SERP؛ حداقل یک تصویر/فرایند/داده/ابزار اصلی؛ منابع اولیه.

روز ۱۰–۱۲: سه صفحه خوشه — نیت متمایز، ارزش اصلی، لینک به ستون + یک هم‌خوشه، CTA مشخص.

روز ۱۳: صفحات تجاری — پیشنهاد دقیق، مشخصات، فرایند قیمت، موجودی، شواهد، محدودیت، FAQ، اقدام تبدیل.

روز ۱۴: لینک داخلی: ستون ↔ خوشه‌ها؛ اطلاعات → تجاری؛ بدون یتیم؛ انکر توصیفی.

هفته ۳
فنی

روز ۱۵: کراول سایت — لینک شکسته، ریدایرکت، متای تکراری، کنونیکال، دستور ایندکس، یتیم.

روز ۱۶: ارسال sitemap کنونیکال؛ بازرسی انواع URL؛ رندر زنده؛ برابری موبایل.

روز ۱۷: LCP — عنصر را پیدا کنید، فشرده کنید، lazy نکنید، TTFB، تست دوباره موبایل.

روز ۱۸: INP — کار طولانی، JS شخص‌ثالث، شکستن handler، تست فیلتر/منو/جستجو/سبد.

روز ۱۹: CLS — ابعاد رسانه، فضای رزرو، فونت، بنر و کاروسل.

روز ۲۰: فقط اسکیمای قابل‌اعمال؛ اعتبارسنجی هر قالب.

روز ۲۱: هر URL قابل‌ایندکس: نیت یکتا، ارزش یکتا، کنونیکال، لینک داخلی، ارزش هزینه کراول.

هفته ۴
آوت‌ریچ

روز ۲۲: یک دارایی لینک‌پذیر — دیتاست، نظرسنجی، ماشین‌حساب، مقایسه قطعی، ویژوال پژوهشی، منبع فنی قابل‌دانلود.

روز ۲۳: ۳۰–۵۰ خبرنگار، ناشر، انجمن، تأمین‌کننده، منبع آموزشی مرتبط.

روز ۲۴–۲۵: پیچ شخصی (مقاله مشخص، چرا کمک می‌کند، داده منحصربه‌فرد، URL)؛ دسته کوچک اول؛ رصد تحویل/پاسخ/پوشش/ارجاع.

روز ۲۶: حداقل ۱۰ جایگزین لینک شکسته مرتبط.

روز ۲۷: Search Console — کوئری رو به رشد، جایگاه ۵–۱۵، CTR پایین، حذف ایندکس، هم‌پوشانی.

روز ۲۸: یک صفحه فرصت بالا را بهتر کنید (ایمپرشن، جایگاه ۵–۱۵، ارتباط تجاری).

روز ۲۹: فرم/تسویه، رویدادها، CTA موبایل، اعتماد کنار تصمیم، attribution ارگانیک.

روز ۳۰: برنامه ۹۰ روزه: نزدیک صفحه یک ← شکاف نیت تجاری ← گسترش خوشه ← دارایی اصلی ← کسب اعتبار مرتبط ← باگ فنی چندصفحه‌ای.

«محتوای خوب» یعنی چه — معیار قابل‌اندازه‌گیری

  • یک نیت غالب؛ جواب اصلی سریع
  • زیرموضوع‌های تصمیم‌ساز پوشش داده شده
  • اطلاعاتی که از خلاصه عمومی به‌دست نمی‌آید
  • نویسنده/سازمان نام‌دار؛ منبع؛ تاریخ، شرایط، محدودیت
  • گام بعدی منطقی؛ قابل‌استفاده روی موبایل
  • ایمپرشن، کلیک یا تبدیل واجد شرایط می‌سازد
  • بدون تغییر URL اصلی قابل به‌روزرسانی است
